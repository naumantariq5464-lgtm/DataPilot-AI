CORE CONCEPT
============
DataPilot AI is an AI-powered autonomous data analysis platform that allows
users to upload CSV datasets and analyze them through natural language
instructions.

Users can ask questions such as:
  - Analyze this dataset and identify important trends.
  - Show me the correlation between different columns.
  - Find missing values and unusual patterns.
  - Generate visualizations for sales performance.
  - Calculate statistical summaries.
  - Identify outliers and anomalies.

The AI generates Python analysis code, executes it inside an isolated Docker
sandbox, analyzes the execution results, and presents understandable insights
and visualizations.

Goal: Make advanced data analysis accessible without requiring users to write
Python code.

SECTION 5 — AI ANALYSIS WORKFLOW (COMPLETE)
================================================================================

Step-by-step workflow that must be fully implemented:

  1.  User uploads a CSV file via the frontend.
  2.  Backend validates the file (format, size, encoding, structure).
  3.  Dataset metadata and preview are generated (columns, dtypes, shape, sample rows).
  4.  User submits a natural-language analysis request.
  5.  Backend prepares the AI prompt (includes metadata + user request).
  6.  Vultr Serverless Inference generates Python analysis code.
  7.  Backend validates the generated code (syntax check, safety scan).
  8.  Code + dataset file are sent to the isolated Docker sandbox.
  9.  Sandbox executes the analysis in isolation.
  10. Results and generated visualization artifacts are collected from sandbox output.
  11. Backend validates and structures the results (JSON format).
  12. Frontend displays insights, statistics, and charts.
  13. If execution fails, the error is captured and analyzed.
  14. AI may generate a corrected version through controlled retries (max retries limit).
  15. Final results (success or graceful failure) are presented to the user.

The workflow must remain traceable and properly handle failures at every stage.

SECTION 8 — STRICT SECURITY REQUIREMENTS
================================================================================

Security is a core architectural requirement, not an afterthought.

NEVER:
  - Hardcode API credentials anywhere in code
  - Commit .env files to version control
  - Expose backend secrets to the frontend
  - Send secrets to the Docker sandbox
  - Execute untrusted AI-generated code in the FastAPI process
  - Run privileged Docker containers
  - Mount Docker socket inside the sandbox
  - Allow unrestricted filesystem access from sandbox
  - Allow unrestricted network access from sandbox

ALWAYS:
  - Apply CPU limits to sandbox containers
  - Apply memory limits to sandbox containers
  - Apply process count limits to sandbox containers
  - Apply execution time limits (timeout)
  - Run sandbox code as a non-root user
  - Validate all uploads (format, size, encoding, content)
  - Validate all generated code artifacts before sandbox submission
  - Clean up temporary containers immediately after use
  - Clean up temporary files after processing
  - Verify user ownership before accessing private datasets
  - Protect all API endpoints with authentication and authorization

Do not mark any security requirement as implemented without actual verification.

SECTION 15 — CRITICAL CLARIFICATIONS
================================================================================

1. VULTR INFERENCE:
   The OpenAI SDK is used ONLY as an HTTP client library.
   All actual AI requests go to Vultr Serverless Inference endpoints.
   The base_url of the OpenAI client is set to the Vultr inference URL.
   No OpenAI credits are used.

2. DOCKER SANDBOX:
   AI-generated Python code is ALWAYS executed inside a Docker container.
   NEVER inside the FastAPI process.
   The container is ephemeral — created fresh, used, then destroyed.

3. CHARTS:
   Every analysis produces DIFFERENT charts based on:
   - The specific user request
   - The data types present in the dataset
   - The columns involved in the analysis
   Multiple chart types may appear in a single analysis response.
   Never show the same static chart regardless of the question.

4. BUDGET:
   $200 USD in Vultr credits available.
   Spend efficiently:
   - Vultr Serverless Inference: per-token billing
   - Vultr Compute VM: hourly billing (shut down when not needed during dev)
   - Vultr Object Storage: per-GB billing
   Monitor usage regularly.

5. PHASE-BY-PHASE DEVELOPMENT:
   Do NOT build everything at once.
   Follow the 12-phase roadmap strictly.
   Each phase must be completed and tested before starting the next.
